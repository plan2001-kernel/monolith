# P0: Plan9-yhteensopivuuden selvitys

Tutkittu 30.10.2026 read-only-9ptermillä ja julkisilla HTTP(S)-pyynnöillä.
Tuotantoasetuksia ei muutettu.

| Kysymys | Havainto | Tulos |
|---|---|---|
| Käyttöjärjestelmä | `/dev/osversion` = `2000`, `/dev/sysname` = `cpu-amd64-poc1`; Plan 9 -palvelin. Tarkka lähdecommit ei näy laitteista. | Osittain varmistettu |
| HTTP-palvelin | Julkinen `Server: rc-httpd`; tcp443 ajaa `tlssrv`-palvelun ja `rc-httpd`:n. | Varmistettu |
| CGI | `/rc/bin/rc-httpd/handlers/cgi` ja `static-or-cgi` ovat asennettuina. Tuotannon `select-handler` ei reititä `/sp/`-polkua CGI:lle. | CGI-tuki asennettu, SP-reitti puuttuu |
| POST | Turvallinen JSON-RPC `POST /mcp` `ping` vastasi 200. `POST /sp/api/v1/status` ei ole käytettävissä. | HTTP POST + C-handlerin JSON-runko varmistettu |
| Binäärinen upload | C-handler voi lukea `Content-Length`-rungon stdinistä. Suuri, mielivaltainen binäärirunko ei ole vielä testattu tuotantoon kajoamatta. | Avoin |
| Atominen julkaisu | Sivuston nykyinen asennus käyttää `.new`-tiedostoa ja `mv`:tä samalla tiedostojärjestelmällä. SP:n kaksoistila-/katkosturvaa ei ole vielä testattu. | Perusmalli löytyy, SP:n takuut avoinna |
| HTTPS | Let’s Encrypt -varmenne kattaa `plan2001.com` ja `auth.plan2001.com`, voimassa 6.1.2027 asti. HTTPS vastaa 200. | Varmistettu |
| IPv4 / IPv6 | A-tietue `82.70.55.84`; IPv4-HTTPS toimii. AAAA-tietuetta ei ole; IPv6-yhteys ei ole tarjolla DNS:n kautta. | IPv4 kyllä, IPv6 ei |
| Resurssit | `/dev/swap` ilmoittaa muistia `1062252544` tavua ja swap-rivin `0/320000`. Julkisen web-puun `du -s` = `445542` (sisältää ISO:n). | Muisti ja web-puun koko luettu |
| Levytila | Palvelimen `df`-komentoa ei ole asennettu. Dokumentaatiossa mainitaan 46.6 GB boot-levy (vanha OCI-kuvaus); vapaa tila jäi mittaamatta. | Avoin |

Julkinen `/sp/` ja `/sp/api/v1/status` palauttavat 404:n. Julkinen `/mcp`
vahvistaa, että nykyinen `rc-httpd` pystyy reitittämään POST-pyynnön Plan 9 C
-käsittelijälle. CGI-tiedostojen olemassaolo ei yksin tarkoita, että niitä
voisi käyttää ilman uutta reititystä.

Julkinen `auth.plan2001.com/` palautti tarkistuksessa saman etusivun kuin
`plan2001.com/`; auth-hostin nykyinen sisältö/reititys pitää korjata ennen
passkey-kirjautumista käyttävää julkaisua.

## Rajaus

P0 ei testannut suuria upload-runkoja, samanaikaisia pyyntöjä, levytilan
riittävyyttä eikä virrankatkaisua kirjoituksen aikana. Nämä kuuluvat paikallisiin
P1–P3-testeihin. Tuotantoon ei lisätty reittiä eikä kirjoitettu tiedostoja.
